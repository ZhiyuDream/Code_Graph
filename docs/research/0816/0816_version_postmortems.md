# 0816 逐版本复盘：每个版本为什么"不行"

> 目的：不跑新实验，把 0807-0809 期间所有版本的轨迹和指标重新过一遍，逐版本回答"为什么不行"——严格区分三种情况：**方法本身不行 / 代码 bug 污染了判断 / 测量噪声内无法判断**。
> 每个版本统一格式：**思路（人话）→ 具体做法 → 人类类比 → 结果（表格）→ 数据分析 → 为什么行/不行**。
> 数据来源：`results/qa_*.json`（每轮轨迹，含 Agent 每步想法/动作/工具返回）、`results/eval_*_det*.json`。旧结果文件全部保留。
> 指标口径：det（答案引用了 gold 文件**且**调查时真读过它才得分）。全量 50 题；失败子集 = 历来 det<100% 的 12-18 道题。

## 0. 系统怎么答题（30 秒版）

1. **召回**：根据问题从两万多个函数里捞出约 100 个候选，Agent 先看前 20 个；
2. **调查**：LLM Agent 有 30 步预算，每步可选：读函数、查谁调用了它、查它调用了谁、搜索符号、列目录/文件清单等。每 5 步一个"监督者"LLM 评价方向；
3. **答题**：汇总调查时读过的代码，生成带引用的答案。

人类工程师做同样的事：先猜问题在哪几个文件，打开读，看到调用顺手点进去，方向错了换目录，记住"这个文件看过了、没用"，最后写结论。**这几天所有改动，都是在补 Agent 和人类工程师之间的差距。**

## 2. 逐版本

### V48：给 Agent 一本"线索账本"

- **思路**：Agent 调查时不断发现新线索（"这函数被谁调了"），以前线索只出现在某一步返回里，翻篇就忘。
- **具体做法**：find_callers/find_callees 发现的调用方/被调方自动登记到 frontier 清单（谁发现的、何时、优先级），每步 prompt 展示，读掉才划掉。
- **人类类比**：工程师便签上记"待查：这函数谁调的？"——防止想到一半忘了。

**结果**：

| 指标 | 基线 | V48 | 变化 |
|---|---|---|---|
| 全量 det | 84.8% | 82.8% | -2.0pp |
| 全引用 / 部分 / 零 | 38/9/3 | 36/11/3 | -2/+2/0 |
| 逐题变化 | — | 升 001/010/014；降 011/012/027/032 | 噪声幅度内 |
| 重复查询拒绝率 | 51% | 30% | **-21pp** |
| 漏引分解（C没搜到/A搜到没读/B读了没引/D编造） | 基线 13/3/1/0 | 12/3/1/2 | C 类持平 |

- **分析**：账本机制本身有效（重复查询拒绝率 51%→30%），但全量指标净零。原因是当时失败题的主死因是"召回压根没给对线索"（C 类），账本记的都是错误区域里的线索——**药对症但病症不对**。

### V49：把函数池换成"文件包"（唯一明确的方法失败）

- **思路**："先找对文件比找对函数容易"，那就直接给 8 个最可疑文件+各自函数清单。
- **具体做法**：召回池**替换**为 top 文件的函数，其他全扔掉。
- **人类类比**：告诉工程师"别管其他文件，就在这几个里找"——猜错文件直接判死刑。

**结果**：

| 指标 | V48 | V49 | 变化 |
|---|---|---|---|
| 失败子集平均 | — | 45.1% | 持平（子集暴露不了伤害） |
| 全量 det | 82.8% | **75.8%** | **-7.0pp，跌出噪声带** |
| 全引用 / 部分 / 零 | 36/11/3 | 33/10/**7** | 零引用翻倍以上 |
| 逐题变化 | — | 升 002/007；降 012/018/027/031/032/038 | 018/031/032/038 满分→0 |
| 漏引分解（C/A/B/D） | V48 12/3/1/2 | **17/5/1/1** | **C 类 +5——视野收窄的直接证据** |

- **分析**：零引用题从 3 暴涨到 7，且跌的全是原来满分的题。轨迹根因：池子被替换成 top 文件的函数后，猜错文件的题里 Agent 没有任何备选方向。**所有既有机制的前提是"视野内什么都有"，收窄视野违反了系统赖以工作的假设。**这是唯一一个"方法本身失败"的版本（已回滚）。

### V50：像人一样逛目录 + 记住看过什么

- **思路**：Agent 之前只盯召回池。人会怀疑某目录→扫一眼→不相关就换→记住看过的目录。
- **具体做法**：① `scan_directory` 目录粗筛（只看函数名，不读代码）；② 目录账本（探索过哪些目录、结论、还剩什么）；③ 相关文件的邻居提示；④ **重读回放**（重读不再拒绝，直接再给内容）。
- **人类类比**：①②是人逛代码库的方式；④像 IDE 的后退键。
- **附带修复**：析构函数 `~xxx` 之前永远读不到（正则 bug）。

**结果**（12 道失败题子集）：

| 指标 | 基线 | V50 | 变化 |
|---|---|---|---|
| 子集平均 det | 36.8% | 51.4% | **+14.6pp** |
| 子集逐题 | — | 5 升 0 降（001/007/034/040/042） | 无回退 |
| 重复拒绝（12 题总步数） | 108 | 44 | -59% |
| 空搜索 | 40 | 6 | -85% |
| 漏引分解（子集 12 题） | 基线 13/3/1/0 | 4/6/0/2 | **C 类 13→4——"找不到"开始变成"没读"** |

- **分析**：子集强正且零回退；浪费结构（重复拒绝/空搜索）断崖式下降。全量未跑（收益幅度在当时的全量噪声带内也看不出来）。埋下两个雷：回放让"监督下令重读"的循环永远成功；回放路径吞掉监督调度（V51/V55 处理）。

### V51：重读超 2 次硬打断

- **思路**：V50 回放的副作用——监督者下令"再读一遍"，Agent 就一遍遍读（回放永远成功，循环打不断）。
- **具体做法**：同一内容回放 2 次后硬拒（"你手里已经有这些代码了"）；监督 prompt 禁止下令重读。
- **人类类比**：带教师傅按住你："这段看三遍了，要么写结论要么看别的。"

**结果**：

| 指标 | V50 | V51 | 变化 |
|---|---|---|---|
| 子集平均 det | 51.4% | 55.6% | +4.2pp |
| 全量 det | （V48 82.8%） | 83.7% | +0.9pp |
| 全引用 / 部分 / 零 | — | 38/8/4 | 零引用 3→4 |
| 逐题变化（全量） | — | 升 001/002/007/010/034；降 011/012/021/031 | 互咬 |
| 漏引分解（C/A/B/D） | 基线 13/3/1/0 | 4/10/0/2 | C 类 13→4 |

- **分析**：当时被判"-1.2pp 回退"是相对基线的读法。事后发现两个 bug：监督输出非 dict 被**静默丢弃**（无日志）+ 监督调度被回放路径跳过——**V51 的监督约束大半没上班**，"监督没用"差点建立在"监督没运行"的数据上。

### V52：给被调函数标上真实的"家住址"

- **思路**：find_callees 只给名字，以前把被调函数的文件错记成当前文件。Agent 按错地址找，读不到，线索烂掉。
- **具体做法**：被调函数进待办前查符号索引确定真实定义文件，明示"它住在别的文件"。
- **人类类比**：IDE 的"跳转到定义"——以前是猜"foo() 应该在本文件"。

**结果**：

| 指标 | V51 | V52 | 变化 |
|---|---|---|---|
| 子集平均 det（两轮均值） | 55.6% | 59.3% | +3.7pp |
| 全量 det | 83.7% | 87.0% / 82.7%（均值 84.8%） | +1.1pp（均值口径） |
| 全引用 / 部分 / 零（均值） | 38/8/4 | 34/14/2 | 零引用 4→2 |
| 归名案例 | — | 014：33→100% | 追到 `llama_model_chat_template` 定义文件 |
| 漏引分解（两轮） | V51 4/10/0/2 | r1 4/9/0/0；r2 3/13/0/0 | C 类压到 3-4，B 类归零 |

- **分析**：机制有归名胜绩，但全量两轮互咬（87.0/82.7），净零。附带泛名误配 bug（`release()` 被解析到无关文件，后加黑名单）。

### V53：进文件先发一份"函数目录"（file-recon）

- **思路**：Agent 几乎从不枚举自己在看的文件（13 个漏引文件只 1 个被列过清单），gold 函数名在眼前也不读。
- **具体做法**：首次读取某文件函数成功时，自动附"该文件共 N 个函数：foo(15-31行)……"——只给名字行号，不给代码。
- **人类类比**：打开新文件先看大纲视图，再决定精读哪段。

**结果**：

| 指标 | 对照 | 数值 | 变化 |
|---|---|---|---|
| 子集同 run 对照（11 题） | A 组（V52 现状）40.9% → D 组（file-recon）57.6% | **+16.7pp** | 4 升 0 降，token ±0% |
| 全量 det（两轮） | V52 均值 84.8% → V53 均值 82.1% | -2.7pp | 噪声内（见下） |
| 全引用 / 部分 / 零（均值） | 34/14/2 → 33/14/3 | — | — |
| 关键旁证 | File Map **未触发**的 25 题（机制与 V52 同构）两轮均值也降 5.0pp | 降幅=纯方差经验值 | 全量无法否决子集证据 |
| 漏引分解（两轮） | V52 4/9、3/13 | r1 8/9/1/0；r2 5/11/1/0 | 持平 |

- **分析**：全量双跑里"机制没碰的题"降得更多——证明全量降幅是运气。同 run 配对子集对照是同分布样本，证据强度更高。**保留上线。**

### V54：集中修 7 个 bug

- **思路**：起手有 bug，方法有没有效的判断全是假的。集中清数据通路的静默截断/格式问题。
- **具体做法**（两个最典型的）：① 记忆缓存只存函数前 1500 字符却标"完整阅读可直接引用"；② find_callers 只找 10 个调用方却报"找到 10 处"。另含监督静默丢弃修复、scan_directory 关键词排序等。

**结果**（18 道失败题子集）：

| 指标 | V53（两轮均值） | V54 | 变化 |
|---|---|---|---|
| 子集平均 det | 50.9% | **63.9%** | **+13.0pp，当时最佳** |
| 归名案例 | — | 032：0→100% | scan 关键词排序直接救回（gold 原被字母序截断） |
| 漏引分解（子集 18 题） | 基线 13/3/0/0 | 3/11/0/0 | C 类 13→3 |

- **分析**：收益主要体现在数据可信度——这批 bug 不修，前面 V50-V53 的结论全部建立在失真数据上。

### V55：监督者考勤修复（中性）

- **思路**：监督者经常"没上班"（触发点在循环末尾，被提前跳过的路径吞掉）。
- **具体做法**：按已完成步数强制触发。

**结果**：

### V57：最重要的线索置顶提醒

- **思路**：044 的三个 gold 文件都被搜索结果/frontier 明确展示过，Agent 一次没跟。把"当前最重要未跟进线索"提到问题正下方，每步都在。
- **人类类比**：便签贴屏幕正中间，而不是笔记本第 30 页。

**结果**（2 题定向验证）：

| 044 | 0% | 33% | 破零 |
| 013 | 33% | 33% | 持平 |

### V58：子 agent 批量读代码打分（内容分诊）

- **思路**：Agent 挑函数靠**名字**猜——013 的 gold 叫 `get_cache_acl_tensor`，名字像"获取 tensor"，代码其实是缓存扩容，看名字必漏。改为开工前子 agent 读真实代码打分。
- **具体做法**：池内前 24 个候选的完整代码（不截断）一次喂给 LLM，每个打 0-10 分；按分数重排，≤3 分跳过。
- **人类类比**：review 前先快速翻一遍所有改动内容再决定细看哪个，而不是只看文件名。

**结果**（18 题失败子集）：

| 指标 | V56 | V58 | 变化 |
|---|---|---|---|
| 子集平均 det | 55.6% | 61.1% | +5.5pp |
| 归名案例 | — | 013：0→33% | 分诊单测 gold 拿 10/10 |
| 漏引分解（子集） | V55 2/13/0/0 | 7/10/2/0 | C 类回升到 7（分诊重排后探索面收窄的副作用） |

- **分析**：有效但有边界——分诊只能重排池内候选，**池子里没有的变不出来**（013/044 的 gold 当时没进池）。

### V59：打分扩到 96 + 超时线索系统直接读（突破版）

## 5. 总结

**失败的五类死因**（每类治理方式完全不同）：

| 死因 | 人话解释 | 代表题 | 治理状态 |
|---|---|---|---|
| 召回锚定 | 一开始就找错了楼层 | 013/044/001 | 分诊+HyDE 部分解决 |
| 选择失明 | 对的就在眼前，没点开 | 032 | 胜率提高未根除 |
| 跟进丢失 | 看到线索，转头就忘 | 014/002/040 | 基本解决 |
| 答案偏写 | 调查了四家，报告只写一家 | 031 | 胜率提高 |
| 测量噪声 | 同一套代码跑两次差 4 分 | 全部硬币题 | 双跑均值压住 |

**失败模式的迁移史**（每轮漏引 gold 文件的归因分解：C 没搜到 / A 搜到没读 / B 读了没引 / D 编造型引用）：

| 版本 | 漏引文件数 | C 没搜到 | A 搜到没读 | B 读了没引 | D 编造 |
|---|---|---|---|---|---|
| 基线 | 17 | **13** | 3 | 1 | 0 |
| V48 | 18 | 12 | 3 | 1 | 2 |
| V49（方法失败） | 24 | **17** | 5 | 1 | 1 |
| V51 | 16 | 4 | 10 | 0 | 2 |
| V52 两轮 | 13/16 | 4/3 | 9/13 | 0 | 0 |
| V53 两轮 | 18/17 | 8/5 | 9/11 | 1/1 | 0 |
| V56 | 18 | 2 | 14 | 2 | 0 |
| V59 两轮 | 14/15 | **1**/3 | 13/12 | 0 | 0 |
| V62 两轮 | 12/19 | 5/5 | 7/14 | 0 | 0 |

**分析**：失败主战场在三年里发生了两次迁移——
1. **基线 → V51**："没搜到"（C 类 13→4）。V50 的目录探索/召回扩展把"找不到"基本消灭了；
2. **V51 之后**：主战场变成"搜到没读"（A 类 9-14 个）——东西在眼前但没读，这就是后来分诊/置顶提醒/自动跟进/种子提级一系列机制的靶子；
3. **"读了没引"（B 类）从 V59 起绝迹**——答案阶段的修复（相关函数必须引用、同族全覆盖）彻底生效；
4. V49 的"C 类暴涨到 17"是它"收窄视野"方法失败的直接证据——漏引分解表比总分更早暴露方法性错误。

**三条元教训**：
1. 这个 benchmark（50 题）× 这个模型的噪声是 ±3-5pp、单题可 100↔0。裁判规则：同 run 配对子集 > 全量双跑均值 > 全量单跑（不可用）。
2. **评估机制之前，先确认机制在运行**（V51 监督、V60/V61 限流都是反例）。
3. bug 修复和方法改进必须分开记账：10 个 bug 每一个都曾让某个方法"看起来不行"。

## 6. 补记 V63：分诊分接入 frontier 优先级（032 选择失明修复）

**起因**：032 在 V62 两轮全零，但 gold `ggml_backend_webgpu_reg` 一直在池内 rank 1-2、分诊 10 分。追查发现三个优先级系统互不相通：分诊分数（10.0）只影响池排序；frontier 优先级里召回种子最高只到 MEDIUM（HIGH 需名字命中问题关键词，"webgpu_reg"不含任何关键词）；自动跟进只盯 HIGH——三发子弹全打在非 gold 上。

**修法**（一行逻辑）：召回种子进 frontier 时，分诊 ≥8.5 分直接给 HIGH——"分诊说重要"和"自动跟进的瞄准镜"接入同一优先级体系。

| 027 | 75% | **100%** | ▲ |

**机制细节**：032 里 gold 实际是被 Agent 在 step 9 自己读的（不是自动跟进的子弹）——优先级接线让它登上了 frontier 顶部展示位和置顶提醒，Agent 第 9 步把它和其他后端 reg 一起批量读了。自动跟进的 3 发子弹（registry/register/zdnn_reg）起了辅助作用。
