## 一、起点问题

0801 交接时的 ReAct 调查（Concept-Symbol 初始定位 + ReAct 扩展）存在四个结构性缺陷：

1. **没有调用链工具**：Agent 只能靠 grep 搜文件名，查不到"谁调用了谁"
2. **读文件截断 5000 字符**：函数看不全，等于白看
3. **防循环硬编码** `search_symbol("device")`：换仓库即失效
4. **答案证据传递靠 500 字符截断的日志**：读过的证据在答案阶段丢失

## 二、失败题目分析（ABC 分类法）

漏引文件按与 Agent 的距离分三类（`scripts/analysis/analyze_coverage_gaps.py`）：

- **A类·调用链可达**：没读，但从已读函数沿 CALLS 图（双向 BFS，8 跳内）能到达
  —— Agent 扩展差一步，属于"差一点点"
- **B类·读过没引**：实际读过（read_function/read_lines），但答案没引用
  —— 答案生成阶段的证据丢失
- **C类·探索未到**：没读且调用链也不可达 —— 召回/方向层问题

（V34 起 B 类判定从 visited_files 改为实际 read 动作——visited_files 含 grep
命中会虚高，修正前 V32 的"B类 8 个"实际只有 1 个真读过。）

## 三、各版本方法与结果

### V19：调查策略重构

- **要解决的问题**：上述四个结构性缺陷
- **方法**：工具拆分为独立函数（`src/qa/tools/react_tools.py`）：
  `read_function`（完整实现不截断）、`list_functions`/`list_files`（Neo4j 函数清单/目录探索）、
  `find_callers`/`find_callees`（grep 调用链）、`expand_recall`（召回池翻页）、
  `mark_file_irrelevant`（文件级不相关标记）；召回池 100 个、首屏展示 20 个；
  通用防循环（同动作同参数拒绝执行）替换硬编码
- **结果**（10 题冒烟）：50.8%，与 V11 的 56% 持平——机制成立但有效性不足，无效步占 40%

### V20：反重复三件套

- **问题**：重复动作被拒后 Agent 不换方向，平均 8/20 步浪费
- **方法**：候选列表动态标注已读状态；拒绝时回放上次结果摘要；动作历史扩到 10 步
- **结果**：50.8% → 60.8%，无效步 40% → 26%

### V21：证据注册表 + 答案生成重构

- **问题**：证据在答案阶段丢失（"访问了但没引用"占漏引 69%）
- **方法**：Agent 维护已读函数注册表（name@file → 完整代码+行号+相关性）；
  答案 prompt = 决策日志 + 已读函数清单 + 相关函数完整实现，废掉 500 字符截断；
  规则"标记相关的函数所在文件必须引用"
- **结果**：并入 V22 一起验证

### V22：机制批次

- **方法**：name@file 复合 key（修同名函数互相覆盖）；批量 read_function；
  find_callees 自动查行号；召回池并入纯 embedding top-50 兜底；
  LLM 关键词抽取（轻量 HyDE）；search_symbol 走 Neo4j 名称索引+grep；
  自动标记不相关文件；token 用量记录
- **结果**：66.7%

### V23：关键词提示 + finish 守卫放宽

- **方法**：LLM 抽取的关键词直接展示给 Agent（可 search_symbol 验证）；
  finish 守卫（相关函数没做调用链调查则拒绝 finish）原来被
  `step_num < max_steps` 条件架空（Agent 都在最后一步 finish），放宽
- **结果**：62.5%

### V23 全量（50 题，第一个全量数据点）

- **结果**：Binary 98%，平均覆盖 76.2%（超 0801 最佳的 73.8%），全引用 29/50

### V24：引用自检 + 方向纠偏

- **方法**：答案生成后程序化检查相关文件是否在答案中（缺失则多轮补答一次）；
  第 6/10 步无任何相关标记 → 注入换方向提示
- **结果**：74.3%（持平）。**关键发现**：漏引真凶是"find_callers 查到了调用点但
  Agent 从不进去读"——grep 命中不算证据

### V25：调用点线索注册

- **方法**：find_callers 返回结构化调用点，finish 守卫升级为
  "相关函数的调用点没读 → 拒绝 finish 并列出清单"
- **结果**：75.0%（平台期）。守卫触发 12 次但都在 19-20 步，**拒绝后没步数补救**

### V26：自动读调用点 + 早期纠偏 + 步数 20→30（本轮最大单步提升）

- **方法**：① find_callers 查到相关函数的调用点后，**系统直接自动读 top-2
  未读调用点实现**进证据注册表，不等 Agent 决定；② 重复被拒第 2 次起升级干预，
  直接列出未读调用点清单；③ max_steps 20→30 给补救留空间
- **结果**：失败子集（21 题）40.5% → **61.9%（+21.4pp）**；全量 79.5%，全引用 35。
  调用链证据占比 0% → 13%

### V27：引用净化 + Supervisor 监督子 agent

- **方法**：① 答案引用了从未读过的文件 → 强制重写（删除或改"无法确认"）；
  ② 每 5 步由独立 LLM 评估方向（正确/可疑/错误+指令+建议关键词），注入 Agent 下一步
- **结果**：失败子集 31.7% → 40.0%。**关键发现**：supervisor 判断极准
  （判"错误"5 次全部一针见血），但 Agent 不听——监督只是 prompt 里的一段话

### V28：强制转向（机制样本不足）

- **方法**：supervisor 判"错误" → 最近在读但无产出的文件结案 + 系统强制执行监督建议动作（限一次）
- **结果**：子集 31.1%。仅触发 3 次，无法判决；机制保留

### V29/V30：三路召回 + RRF

- **问题**：永久零题诊断发现两类召回层根因——gold 函数 embedding 全库排名
  1200-19000 进不了任何 top-K（召回失败）；embedding 兜底追加在概念池尾部、
  排名 30 的 gold 永远展示不到（池结构缺陷）
- **方法**：① 关键词直接召回——LLM 猜的符号直接查函数名索引，命中顶到候选最前；
  ② RRF 融合 `1/(60+rank)`（两路分数尺度不同，按分数排序会让兜底沉底）；
  ③ 答案 prompt 以"已读函数清单"为证据唯一标准
- **结果**：子集 44.4% → 56.1%；001（embedding 1401 名）首次 0→100%
- **事故**：V30 全量一度崩到 61%——引用净化 regex 把 `.cpp` 截成 `.c`
  （交替匹配顺序错误），误判真实证据为编造引用并删除。修复后 V30b 全量 78.7%

### V31：条件注入（修双刃剑）

- **问题**：关键词无条件顶置，在召回池本来就好的题上劫持出发点
  （021 被注入的错误符号带偏 30 步，100→0）
- **方法**：召回池 top-20 已有函数名包含任一关键词 → 池子方向已对，跳过注入；
  完全对不上才注入。同时做反过拟合清理（删除工具代码里 llama.cpp 专属的前缀硬编码）
- **结果**：全量 80.5%，全引用 36；回退题 3/4 救回

### V32：MMR 多样性召回 + supervisor 重新召回 + 上下文预算批量读

- **问题**：后端识别题"起始地图错"——候选首屏被单一后端/目录占满
- **方法**：① MMR 重排（score/(1+0.5×同目录已选数)）；② supervisor 判错时用其
  关键词重新召回注入池前列；③ 批量读按 100k 字符预算而非个数
- **结果**：失败子集 30.4% → 52.4%（+22pp，0 下降）；全量 81.0%

### V33/V34：grep 命中即跟进 → 条件跟进

- **问题**："得到了文件名没进去读"——search_symbol 只给文件名单，Agent 不跟进
- **方法**：V33 命中后系统自动读 top-2 名称匹配函数；V34 发现这在正轨题上是噪声
  （5 道满分题回退），改为**只在没找到任何相关函数时启用**
- **结果**：V34 全量 86.0%，全引用 39，Binary 100%。
  **沉淀原则："机制只在需要时触发"**——条件注入、条件跟进、守卫只拒一次

### V35：结束前兜底取证

- **问题**：部分引用全是"调用点枚举不全"；撞步数上限的题 finish 守卫不触发
- **方法**：答案生成前把未读调用点线索自动补读 top-3
- **结果**：84.3%（与 V34 持平，机制无害保留）

### V36-V38：调用点归属修复（judge 口径最高点）

- **问题**："探索未到"五类归因中，"查到了没读"的根因最深——
  `grep_callers` 词法分析定不了归属函数时返回空名字，gold 调用点全被过滤
- **方法**：空归属调用点用 Neo4j 函数行号表补全；决策失败重试×2
  （002 曾因一次 LLM 解析失败整题投降）
- **结果**：全量 87.3%，全引用 42，调用链证据占比 29%

### V39：分诊实验（证伪留档）

- **想法**：凭名称+签名跳过明显不相关候选，省 token
- **结果**：14 道题 0 次使用——与"必须看完整实现才能判断相关性"的铁律冲突，
  LLM 一致选择不跳。与历史结论一致（0620：仅签名筛选≈0 增益；0622：路径预筛崩）
- **结论**：名称+签名信号不足以安全丢弃候选；机制保留不再推进

### SkillOpt 去敏试点

- **背景**：参照 microsoft/SkillOpt（arXiv 2605.23904）——把调查策略当作
  可训练文本状态，冻结 worker 模型，离线优化
- **方法**：策略段抽成外部 `data/qa_skill.md`；失败轨迹反思 → 有界编辑（≤4 条）
  → **去敏防线**（编辑禁止含具体符号/文件/目录/后端名，防过拟合）→ 门控验证
- **结果**：epoch 1 门控 46.7%→51.7%（+5pp），epoch 2 → 55.0%，均采纳。
  学到的规则：子问题拆解、回答前证据核对——与人工迭代写的规则同类但流程自动化

### V40：目录探针 + 关键词多采样 + e2 技能

- **方法**：① 目录级关键词探针（关键词在函数名索引中按目录统计命中密度，
  给 Agent 数据支撑的子系统方向提示）；② 关键词双采样取并集
- **结果**：judge 口径 91.3%/全 44——**此数字后被证明虚报，见 0804 文档**
