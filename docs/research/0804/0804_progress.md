## 1. 指标校正：LLM citation judge 幻觉虚报

- **问题**：V40 的 91.3%/全引用 44 好得可疑，需要独立验证
- **方法**：纯程序化硬核对——gold 文件**出现在答案文本/引用清单**（全路径或 basename）
  **且调查中被实际读过**（read_function/read_lines/系统自动读取）才算引用
- **发现**：judge 声称答案"多次明确提及完整路径"（如 `ggml-sycl/common.cpp:77`），
  但这些路径在答案文本中根本不存在（001/012/014/040：judge 100% vs 硬核对 33%）——
  **judge 在幻觉引用**。假阳性约 10pp，假阴性为零，所有历史 judge 绝对分都含此水分
- **落地**：`evals/eval_v2.py` 新增 `--citation-mode det|llm|both`；
  判定标准经用户确认（清单算引，但必须实际读过，防止塞召回池路径骗分）。
  **后续所有评估以 det 为准**

## 2. 漏引归因：为什么"未读未引"是主流

### 2.1 ABC 分类回顾（0802 建立）

- **A类·调用链可达**：没读，但从已读函数沿 CALLS 图可达（差一跳）
- **B类·读过没引**：实际读过但答案没引（答案层丢证据）
- **C类·探索未到**：没读且不可达（召回/方向层）

演进：V23 时 B 类占 69%（证据传递丢失）→ V26 自动读调用点后 B 类大减 →
V34 起 B 类清零，**只剩 C 类（方向失败）**。

### 2.3 一条完整的失明链（C 类的成因）

抽查 14 个"未读未引"文件：**12 个既不在召回池、也没在任何工具结果里出现过**——
Agent 不是看到了不读，是从头到尾没见过这些文件名。漏引文件几乎全是核心符号的
**call site**，而 call site 进入视野的唯一路径是：核心符号被读 → 标相关 →
find_callers → 调用点进线索清单。断链点在第一环：**关键词抽取没猜中核心符号**，
之后召回池、find_callers、兜底全部无从发力。
**调用链机制只能放大正确的种子，种子缺席时整条链是全黑的。**

## 3. 修复尝试一：关键词兜底读（一成一留一回退）

- **问题**：系统自己抽取的关键词（核心符号），Agent 围着它调查却没读它本身
- **方法**：答案生成前，若没有任何已读函数名包含某关键词，
  从名称索引读最匹配的 top-1 补进证据
- **结果**：
  - v1（首个命中即读）：子集 34.3%→44.4%，021 破零 → **保留**
  - v2（相似度排序：精确>前缀>包含）：中性 → **保留**
  - +1跳（再读定义的 top-2 调用方）：**净负回退**——无关证据稀释答案焦点，
    对照 003 从 75% 拉到 50%
- **失败教训**：关键词猜错时所有下游机制都无从发力（002 兜底读到的是
  `tensor_type_fallback` 等干扰项）；自动塞证据必须严格相关，否则稀释焦点

## 4. 修复尝试二：函数族机制（V42/V43，部分证伪）

- **问题**：同一关键词可能命中多个"函数族"（`chat_template` 命中
  `llama_model_*`/`common_chat_*`/`llm_chat_*` 三族），只读一族会漏定义层
- **方法**：召回时构建关键词→函数族映射展示给 Agent；族级兜底补读（每族没读就补）
- **结果**：族展示让 001 单轮 0→33%（信息有效）；但族级强制兜底把噪声函数
  塞进证据注册表（V42 子集 40.7%→35.2%，净负面）——**族级兜底回退，仅保留族展示**；
  V43 全量 det 79.5%，与前几版同处噪声带

## 5. 修复尝试三：符号假设验证回路（V44）

- **问题**：关键词抽取单轮猜错就没有任何补救（顽固题的直接根因）
- **方法**：关键词抽取（双采样并集）→ 名称索引验证命中/未命中+命中族示例 →
  反馈给 LLM 修正一轮 → 并集进召回
- **离线验证**：002 修正轮直接猜中 `llama_model_chat_template`（第一轮只到族，
  修正轮给出精确符号）；完全无锚题（013/044）两轮都失败
- **结果**：靶题子集 36.7%→53.3%（+16.6pp，031/040 破百，0 下降）；
  全量 det 82.8%——与 V41 持平（噪声内），031 在全量轮又回到零

## 7. 总结论

1. **V38 后进入平台期**：V38-V44 在 det 下为 79.5%-82.8% 的噪声带。
   后续机制（兜底读、函数族、验证回路）在失败子集上次次 +10~25pp，
   但全量上被高方差题的反复横跳抵消。
2. **剩余 4-5 道零引用（001/013/031/032/044）是"单次成功率"问题**：
   每道题在不同轮次都被做对过，但没有任何一轮能同时做对——
   机制已把"可能性"打开，缺的是**稳定性**。
3. **下一步候选路径**：①多次采样取最优（self-consistency，直接吃方差，
   与现有机制正交）；②SkillOpt 继续 epoch 迭代技能；③换更强模型。
   其中①成本最低（只是多跑几遍），可能最划算。
