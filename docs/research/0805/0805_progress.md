## 一、这是什么

**任务**：对代码仓库（llama.cpp @ a6cc43c2，750 文件 / 23689 函数 / 26186 CALLS 边）
做 AI 生成代码的审计问答。50 道中文审计题（如"AI 生成了设备切换相关实现，
现有调用方主要依赖什么行为？失败或重复切换时会不会破坏调用方假设？"），
系统需要找到相关代码证据（文件:行号）并给出带引用的答案。

**评分**：Binary（答案对不对，LLM judge）+ Citation Coverage（gold 证据文件的引用比例）。
Citation 以 **det 确定性核对**为准：gold 文件出现在答案文本/引用清单
（全路径或 basename）**且调查中被实际读过**才算引用。llm judge 存在约 +10pp
幻觉虚报（附录 A），仅存档参考。

**图数据与抽象层**（离线构建，全程未变）：
- Tree-sitter 建图写入 Neo4j：750 文件 / 23689 函数 / 26186 CALLS 边
- Louvain 社区发现：196 modules / 1656 concepts
- 函数级 embedding 索引 23689 条（text-embedding-3-small）

**最终系统架构**：

```
中文问题
  ↓ LLM 关键词抽取（双采样并集 ≤12）→ 名称索引验证 → LLM 修正一轮（V44 验证回路）
  ↓
三路召回 + RRF 融合：Concept 聚类 top-100 + embedding top-50 + 关键词名称命中（条件注入）
  ↓ MMR 多样性重排（同目录惩罚）
ReAct 调查 Agent（deepseek-v4-flash，max 30 步，workers 25-30）
  工具：read_function / read_lines / list_functions / list_files /
        find_callers / find_callees / search_symbol / expand_recall /
        mark_file_irrelevant / skip_candidates / finish
  机制：防循环拒绝 / finish 守卫 / 自动读调用点 / 方向纠偏 /
        每 5 步 Supervisor 监督 / 结束前兜底取证 / 引用净化
  ↓
答案生成（证据注册表驱动：只引用实际读过的函数）
  ↓
评估（det 确定性核对）
```

## 二、失败模式的度量框架（ABC 分类）

每个漏引文件按与 Agent 的距离分类（`scripts/analysis/analyze_coverage_gaps.py`）：

- **A类·调用链可达**：没读，但从已读函数沿 CALLS 图（双向 BFS ≤8 跳）能到达 → 扩展差一步
- **B类·读过没引**：实际读过（read_function/read_lines）但答案没引用 → 答案生成丢证据
- **C类·探索未到**：没读且调用链不可达 → 召回/方向层问题

注意：A/B/C 只统计**部分引用题**的漏引文件；零引用题的全部漏引本质上都是 C 类。
**口径陷阱**：题目在零↔部分之间迁移时，它的漏引文件会随之进入/离开统计——
零降部升会让 C 类"变多"（其实是进步的痕迹），部分跌回零会让 C 类"变少"
（其实是退步）。读表时必须结合零/部分/全的数量一起看。

- **背景诊断**（永久零题的召回池解剖）：gold 函数 embedding 全库排名——

### 3.10 V39/V46：分诊实验（三次证伪，最终判决）

- **想法**：凭名称+签名跳过明显不相关候选，省 token
- **V39**（铁律+分诊动作 `skip_candidates`+finish 安全网）：
  14 道题 0 次使用——与"必须看完整实现才能判断相关性"铁律冲突
- **V46 对照实验**（移除铁律 + 分诊优先 skill `data/qa_skill_triage.md`，
  通过 `QA_SKILL_PATH` 切换）：8 道题（4 失败+4 顺利）**依然 0 次使用**
- **V46b（prompt 逐行核查版）**：用户坚持核查实际发出的 prompt，发现两处铁律残余
  （"读实现是确认相关性的最终依据"、skip_candidates 描述里的"慎用"警告），
  全部清除后重跑：**依然 0 次使用**。且池子里确实存在人类眼中明显可跳的候选
  （examples/tools 里的 main、Android JNI 包装等），模型照读不误
- **最终结论**：彻底排除 prompt 因素后，**模型的先验就是"宁可全读也不排除"**——
  对跳错的恐惧远大于省 token 的动机，prompt 无法改变。
  历史上也一致（0620 仅签名筛选≈0 增益、0622 路径预筛崩到 1.8%）。
  若想省 token 只剩确定性分诊（系统按规则过滤，如 vendor/tests/examples 降权），
  不依赖模型配合，但收益预期有限
- **最终结论**：不是铁律拦着，是**模型的先验就是"宁可全读也不排除"**——
  对跳错的恐惧远大于省 token 的动机，prompt 无法改变。

## 附录 C：关键方法的精确参数（答辩口径）

### 召回与排序

**Concept-Symbol 召回**（`concept_symbol_retrieve_functions`）：
- concept 层：每个 concept 得分 = 其内全部函数 embedding 与问题 embedding 余弦相似度的**最大值**，取 top-20 concepts
- 函数层重排：`score = sim + 0.5 × symbol_score`
- symbol_score：问题正则抽取的标识符（小写、camelCase 拆词、去停用词）
  命中函数名 +2.0、命中文件路径/签名/正文 +1.0，归一化除以 `2 × 关键词数`
- 池大小 top-100，首屏展示 20

**RRF 融合**（V30 起）：两路召回（concept 池 100、纯 embedding top-50）按
`score(f) = Σ_路 1/(60 + rank_路(f) + 1)` 融合排序，k=60（标准值）。
选 RRF 的原因：两路分数尺度不同（concept 路含 +0.5×symbol 加成，embedding 路只有裸 sim），
直接按分数排序会让 embedding 兜底永远沉底（031 案例：embedding 排 30 名却进不了首屏）

**MMR 多样性重排**（V32 起）：贪心选取，每步选
`argmax_f  score(f) / (1 + 0.5 × 已选中与 f 同目录的个数)`；
目录 = 文件的父目录。目的：首屏 20 个候选不被单一后端/子系统占满

**关键词抽取**（V22 起）：LLM 从中文问题猜 C++ 标识符（≤8 个），
双采样取并集（≤12）；V44 起加验证回路——名称索引返回命中/未命中+命中族示例，
LLM 修正一轮，并集上限 16

**条件注入**（V31 起）：召回池 top-20 的函数名（小写拼接）包含任一 ≥4 字符的关键词
→ 判定池子方向已对，跳过注入；否则名称索引命中的函数以 score=1.0 顶置（≤10 个）

### Agent 机制

**自动读调用点**：find_callers 返回后，未读的调用点按返回顺序自动 read_function
top-4（V26 时 top-2，V38 起 top-4）；search_symbol 的跟进读 top-2 且仅在
"尚无相关函数"时启用（条件跟进）

**finish 守卫**：存在"标记相关但没做过 find_callers/find_callees 的函数"或
"相关函数的调用点线索未读" → 拒绝 finish 一次并列出清单（≤5 个）；只拒一次防死循环

**防循环**：同一 (action, 参数) 第二次执行直接拒绝并回放上次结果；
第 2 次被拒起附升级干预（相关函数清单+未读调用点+具体建议）

**Supervisor**：每 5 步评估一次（输入：问题/已读函数/文件状态/未读线索/最近 5 步），
输出 direction（正确/可疑/错误）+ 指令 + 建议关键词；判"错误"时强制转向一次
（执行建议的 search_symbol/expand_recall）并把最近 5 步无产出的文件结案

**批量读预算**：单步 observation ≤ 100k 字符（≈25k tokens），单批 ≤8 个函数；
单函数 >25k 字符时只显示头部 6k + read_lines 引导（完整代码仍进证据注册表）；
答案阶段单函数 >30k 字符保留头 15k+尾 10k 并标注省略行数

**方向纠偏**：第 6/10 步仍无任何相关标记 → 注入换方向提示（附关键词提示）

**结束前兜底取证**：答案生成前，未读调用点线索补读 top-3；
关键词兜底读（已读函数名不含某关键词时读名称索引最匹配 top-1，精确>前缀>包含）

### 评估

**det 判定**：gold 文件 f 满足 `(f 全路径 ∈ 答案文本) ∨ (basename(f) ∈ 答案文本)`
**且** `f ∈ 实际读过集合`（read_function/read_lines 的 files_accessed +
系统自动读取的文件），计为引用。coverage = 被引 gold 文件数 / gold 文件总数
（gold 证据去重到文件级，排除 .h/.hpp）
